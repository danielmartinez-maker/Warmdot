# Tilemaps and edit history
Tilemaps store occupied cells in sparse 32 by 32 chunks using Forge's +X right and +Y down world convention. Chunk coordinates use Euclidean division, so negative world cells map to a stable non-negative local index. Empty chunks are removed when the last tile is erased.

Tilemap documents use a versioned JSON schema. Chunks and cell entries serialize deterministically in sorted coordinate/index order. Each map stores its cell size in world units and its source tile size in PNG pixels; older documents default to 16 by 16 pixel tiles. Validation rejects duplicate chunks/cells, empty serialized chunks, invalid world or source tile sizes, out-of-range indices, and rotations outside zero to three quarter-turns.

A paint stroke records the original and final value once per touched coordinate. TileMapHistory applies each stroke as one undo entry, supports redo, caps retained edits, and tracks the saved state even when edits branch after an undo. The native editor's Tilemap workspace loads and saves `Assets/Default.forgetilemap.json`. It selects a PNG tileset and tile index, paints with left-drag, erases with right-drag or the erase toggle, records solid-cell metadata, and groups each drag into one bounded undo/redo stroke. The player imports this default map into the runtime scene as textured tile sprites and creates fixed box colliders for solid cells. The first runtime path expands cells into ordinary scene objects, so chunk-aware render extraction and collision optimization remain future work.
